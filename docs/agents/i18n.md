# Internationalization (i18n)

## Setup

Configured in `nuxt.config.js` via `@nuxtjs/i18n`:

- **Default locale:** German (`de`)
- **Available locales:** German (`de`), English (`en`)
- **Strategy:** `no_prefix` — one path per page in every language; the locale is carried by the
  `i18n_redirected` cookie. Do not switch to a prefixed strategy without first routing every link,
  redirect and middleware guard through a locale-aware helper: about sixty of them assemble raw
  paths today, and `useTenantRoute().isActivePath` compares `route.path` against one.
- **Switching:** `setLocale(code)` from `useI18n()` — it writes the cookie and re-renders in place
- **Locale files:** `i18n/locales/de.json`, `i18n/locales/en.json`

## Usage in components

```vue
<script setup>
const { t, locale } = useI18n();
</script>

<template>
  <h1>{{ t("catalog.title") }}</h1>
  <p>{{ t("checkout.summary.total", { amount: formattedPrice }) }}</p>
</template>
```

## Key structure

Keys are nested by feature area:

```json
{
  "catalog": {
    "title": "Katalog",
    "search": {
      "placeholder": "Suchen…"
    }
  },
  "checkout": {
    "contact": {
      "title": "Kontaktdaten"
    }
  },
  "errors": {
    "noCatalog": "Katalog nicht gefunden"
  }
}
```

## Conventions

- **Always add both locales** — every new key must exist in `de.json` AND `en.json`
- **German is the source locale** — write German text first, then translate to English
- **Use nested keys** — group by feature (`catalog.`, `checkout.`, `auth.`, `account.`, `errors.`)
- **Interpolation** — use `{param}` syntax: `t("checkout.items", { count: 3 })`
- **No hardcoded strings** — all user-facing text must go through i18n, including button labels, error messages, and placeholders
- **Page titles** — use `usePageTitle()` composable which reads from i18n keys

## Adding new translations

1. Add the key to `i18n/locales/de.json` (German text)
2. Add the same key to `i18n/locales/en.json` (English text)
3. Use `t("your.key")` in the component — never hardcode the string

```json
// de.json
{
  "bookables": {
    "availability": {
      "noSlots": "Keine verfügbaren Zeiten"
    }
  }
}

// en.json
{
  "bookables": {
    "availability": {
      "noSlots": "No available time slots"
    }
  }
}
```

## Pluralization

Use pipe syntax for plural forms:

```json
{
  "bookings": {
    "count": "Keine Buchungen | Eine Buchung | {count} Buchungen"
  }
}
```

```javascript
t("bookings.count", bookingCount, { count: bookingCount });
```

## Locale-aware formatting

Use composables for locale-dependent formatting:

- `useFormatting()` — dates, times, prices, numbers
- Pass `locale` from `useI18n()` when formatting outside components

## What to avoid

- Hardcoded German or English strings in templates or scripts
- Adding keys to only one locale file
- Translating developer-facing log messages or comments
- Using `$t()` in `<script setup>` — use `t()` from destructured `useI18n()`
